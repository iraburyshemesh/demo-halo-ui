# Synthetic Pendo usage dataset

Three JSON files, generated by
[`scripts/generate-usage-data.mjs`](../../scripts/generate-usage-data.mjs) and
typed by [`schema.ts`](./schema.ts). Shapes mirror what the Halo app
([`demo-hello-app`](https://github.com/iraburyshemesh/demo-hello-app)) sends to
Pendo, so the data is interchangeable with a real Pendo export.

## `accounts.json` — Pendo accounts (Halo workspaces)

| Field | Type | Mirrors |
| --- | --- | --- |
| `id` | `string` (uuid) | account id |
| `name` / `companyName` | `string` | workspace company name |
| `companySize` | enum | `CompanySizeEnum` |
| `industry` | enum | `IndustryEnum` |
| `planTier` | `Free` \| `Pro` \| `Enterprise` | `PlanTierEnum` |
| `createdAt` | ISO 8601 | workspace `createdAt` |

## `visitors.json` — Pendo visitors (Halo users)

Fields match `pendo.identify({ visitor })` in `src/pendo/pendoIdentity.ts`:
`id`, `accountId`, `email`, `full_name`, `firstName`, `lastName`, `username`,
`jobTitle`, `role`, `yearsExperience`, `location`, `primaryUseCase`,
`teamSize`, `topGoals`, `createdAt`, `signedInAt`. No `passwordHash` — this is
analytics data, not auth state.

## `events.json` — usage events (sorted oldest → newest)

| Field | Type | Notes |
| --- | --- | --- |
| `visitorId` | `string` | FK → `visitors.json` |
| `accountId` | `string` | FK → `accounts.json` |
| `type` | `track` \| `page` | track event vs. page view |
| `name` | `TrackEventName` \| `PagePath` | track names mirror `PENDO_TRACK_EVENTS`; page paths mirror Halo routes |
| `timestamp` | ISO 8601 | within the visitor's lifetime and the last 90 days |
| `properties` | object | per-event, PII-free, mirrors Halo's track payloads |

Track-event properties follow Halo's rules: no `visitorId`/`accountId`
duplication, no PII, no free-text (lengths/counts instead of raw strings).
